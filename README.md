# Nawah Project - New Member System

A modern, responsive web application built for the Nawah Project to manage and showcase new member information. This system provides an intuitive interface for viewing member details and project overviews.

## 🚀 Features

- **Responsive Design**: Fully responsive layout that works seamlessly across all devices
- **Modern UI**: Built with Material-UI components for a polished, professional look
- **Fast Performance**: Powered by Vite for lightning-fast development and optimized builds
- **Routing**: Client-side routing with React Router for smooth navigation
- **Modular Architecture**: Well-organized component structure for easy maintenance

## 🛠️ Tech Stack

- **React 19.1.1** - Modern UI library with latest features
- **Vite** - Next-generation frontend tooling (using Rolldown)
- **Material-UI (MUI) 7.3.5** - Comprehensive React component library
- **React Router DOM 7.9.5** - Declarative routing for React
- **Emotion** - CSS-in-JS styling solution
- **ESLint** - Code quality and consistency

## 📋 Prerequisites

Before you begin, ensure you have the following installed:

- **Node.js** (v16 or higher recommended)
- **npm** (comes with Node.js)

## 🔧 Installation

1. **Clone the repository**

   ```bash
   git clone https://github.com/Nawah-Project/New-Member-System.git
   cd new_member_system
   ```

2. **Install dependencies**
   ```bash
   npm install
   ```

## 🚦 Getting Started

### Development Mode

Start the development server with hot module replacement:

```bash
npm start
```

The application will be available at `http://localhost:5173` (or another port if 5173 is in use).

### Build for Production

Create an optimized production build:

```bash
npm run build
```

The built files will be in the `dist` directory.

### Preview Production Build

Preview the production build locally:

```bash
npm run preview
```

### Linting

Run ESLint to check code quality:

```bash
npm run lint
```

## 🤝 Contributing

We welcome contributions from the community! There are two ways to contribute to this project:

### Option 1: Fork the Repository (Recommended for External Contributors)

1. **Fork the repository**

   - Click the "Fork" button at the top right of the [repository page](https://github.com/Nawah-Project/New-Member-System)
   - This creates a copy of the repository in your GitHub account

2. **Clone your fork**

   ```bash
   git clone https://github.com/YOUR-USERNAME/New-Member-System.git
   cd New-Member-System
   ```

3. **Add the upstream remote**

   ```bash
   git remote add upstream https://github.com/Nawah-Project/New-Member-System.git
   ```

4. **Create a new branch**

   ```bash
   git checkout -b feature/your-feature-name
   ```

5. **Make your changes**

   - Write your code
   - Follow the existing code style
   - Test your changes thoroughly

6. **Commit your changes**

   ```bash
   git add .
   git commit -m "Add: brief description of your changes"
   ```

7. **Push to your fork**

   ```bash
   git push origin feature/your-feature-name
   ```

8. **Create a Pull Request**

   - Go to your fork on GitHub
   - Click "Compare & pull request"
   - Fill in the PR template with details about your changes
   - Submit the pull request

9. **Keep your fork updated**
   ```bash
   git fetch upstream
   git checkout main
   git merge upstream/main
   git push origin main
   ```

### Option 2: Clone Directly (For Team Members with Write Access)

1. **Clone the repository**

   ```bash
   git clone https://github.com/Nawah-Project/New-Member-System.git
   cd New-Member-System
   ```

2. **Create a new branch**

   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make your changes and commit**

   ```bash
   git add .
   git commit -m "Add: brief description of your changes"
   ```

4. **Push your branch**

   ```bash
   git push origin feature/your-feature-name
   ```

5. **Create a Pull Request**
   - Go to the repository on GitHub
   - Click "Compare & pull request"
   - Get your changes reviewed and merged

### Contribution Guidelines

- **Code Style**: Follow the existing code style and conventions
- **Commit Messages**: Use clear, descriptive commit messages
  - `Add:` for new features
  - `Fix:` for bug fixes
  - `Update:` for updates to existing features
  - `Refactor:` for code refactoring
- **Testing**: Test your changes before submitting
- **Documentation**: Update documentation if needed
- **One Feature Per PR**: Keep pull requests focused on a single feature or fix
